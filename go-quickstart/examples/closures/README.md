# Go 闭包 vs JS 闭包

同一组例子，两种语言并排跑：

```bash
go run ./examples/closures        # Go 版
node examples/closures/demo.mjs   # JS 对照版
```

## 逐条对照

| # | 例子 | Go | JS | 结论 |
|---|---|---|---|---|
| 1 | 计数器 | `inc, get := newCounter()` | 返回 `{inc, get}` | **一样** |
| 2 | 捕获变量 | 外部改成 100 → `f()` 返回 100 | 同 | **一样**（都捕获变量，不捕获值） |
| 3 | 显式捕获值 | 传参进构造函数 | 同 | **一样** |
| 4 | 循环变量 | 1.22+ 每轮独立 → `0 1 2` | `let` → `0 1 2`；`var` → `3 3 3` | Go 1.22 追平 `let` |
| 5 | 异步/并发回调 | goroutine，**要加锁** | 单线程，**不用锁** | **本质差异** |
| 6 | 给函数加方法 | `type IntFunc func(int) int` + 方法 | 只能包成 class | Go 独有 |
| 7 | memoize | 闭包 + map | 闭包 + Map | **一样** |
| 8 | 递归闭包 | 先 `var fib func(int) int` 再赋值 | `const fib = n => ...` 直接可用 | Go 稍繁琐 |
| 9 | 延迟执行 | `defer`（参数立即求值，闭包延迟） | `try/finally` | Go 更细粒度 |

## 实测输出

**Go**

```
1) 计数器: 3
2) 捕获变量: f() = 100 （外部改成 100 了）
3) 显式捕获值: g() = 7 （外部 y 变了也不受影响）
4) 循环变量: 0 1 2
5) 三个 goroutine 拿到的 i: [2 1 0] （顺序不定）
6) 函数类型的方法 Twice(5) = 20
7) memoize: 16 16 16 25
8) 递归闭包 fib(10) = 55
9) defer 闭包（执行时读）: 2
9) defer 参数（立即求值）: 1
```

**JS**

```
1) 计数器: 3
2) 捕获变量: f() = 100 （外部改成 100 了）
3) 显式捕获值: g() = 7 （外部 y 变了也不受影响）
4a) var 循环: [ 3, 3, 3 ]
4b) let 循环: [ 0, 1, 2 ]
6) 包成对象后才能加方法 twice(5) = 20
7) memoize: 16 16 16 25
8) 递归闭包 fib(10) = 55
9) finally 里读 x（执行时求值）: 2
5) setTimeout 拿到的 k: [ 0, 1, 2 ]
```

## 亲手验证 4 号例子

`go.mod` 里的 `go` 指令决定循环变量语义：

```bash
# 改成 go 1.21 后运行 → 4) 循环变量: 3 3 3   ← 和 JS 的 var 一样
# 保持 go 1.24      → 4) 循环变量: 0 1 2     ← 和 JS 的 let 一样
```

同一份代码、只改一行模块指令，输出就从 `[3 3 3]` 变成 `[0 1 2]`。
这正是 JS 从 `var` 到 `let` 的那场修复，Go 在 1.22 做了同一件事。

## 差异速查

| 维度 | JS | Go |
|---|---|---|
| 捕获对象 | 变量（词法环境） | 变量（逃逸到堆） |
| 循环变量 | `var` 共享 / `let` 每轮 | 1.21- 共享 / 1.22+ 每轮 |
| `this` | 动态绑定，箭头函数捕获词法 this | **没有 this**，接收者显式传 |
| 并发 | 单线程，天然无竞争 | 真并行，**必须自己加锁** |
| 类型 | 动态 | 静态，闭包有明确 `func(T) U` 类型 |
| 函数可比较 | 引用比较 | **只能和 nil 比** |
| 函数属性 | 有 `name` / `length` / 可挂属性 | 没有 |
| 方法 | 无（包成对象） | 具名函数类型可加方法 |
| 延迟执行 | `try/finally` | `defer`（LIFO） |

## 三个 Go 特有的坑

### ① 并发写闭包变量

```go
n := 0
go func() { n++ }()   // data race，-race 会直接报出来
```

JS 里同样代码是安全的（单线程事件循环）。Go 里必须用 `sync.Mutex` / `atomic` / channel。

### ② 闭包持有大对象导致 GC 无法回收

```go
big := make([]byte, 100<<20)
handler := func() { use(big[:10]) }   // 只用了 10 字节
```
整个 100MB 因为被闭包引用而无法回收。**用完把 `big = nil`，或只捕获需要的那部分。**

### ③ 热路径反复创建闭包

```go
for i := 0; i < 1e6; i++ {
	f := func() { ... }   // 每次都分配
	f()
}
```
闭包捕获了变量就要分配堆对象。热路径里把闭包提到循环外。

## 什么时候用闭包，什么时候用 struct

Go 社区的口诀反过来：**"闭包是穷人的对象"，但 Go 里对象不穷。**

| 用闭包 | 用 struct + 方法 |
|---|---|
| 一次性回调、`http.HandlerFunc` | 有多个方法、要复用 |
| 中间件、Option 模式 | 需要实现接口 |
| 短生命周期的状态封装 | 长期存在的状态 |
| 函数式组合（memoize/pipe） | 需要 JSON 序列化 |
